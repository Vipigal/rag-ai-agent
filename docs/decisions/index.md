# Decision Records

Architecture and project decisions, one concept per decision, numbered
sequentially. See the [Authoring Guide](/docs/authoring-guide.md) for the
format. Superseded decisions are deprecated, never deleted.

- [0014 — Error semantics: one body shape, four statuses, fail-fast startup, a readiness check and a documented OpenAPI](0014-error-semantics-and-startup-validation.md) - Every error is one `{"detail": …}` sentence whose status names who is at fault; adapters translate infrastructure failures, the lifespan validates configuration before the first request, and `/health` reports readiness.
- [0013 — Citations are verbatim passages resolved by containment](0013-citations-as-quotes.md) - The model quotes passages instead of naming chunk ids; each quote is resolved by normalized containment over the chunks it saw, and what cannot be found is dropped and counted.
- [0012 — Page chunks with unit vectors, Gemini embeddings, LLM fallback](0012-page-chunks-unit-vectors-and-providers.md) - The chunk is the page and the vector is the unit (recall@5 0.81 → 0.86); the embedder becomes `gemini-embedding-001` (0.86 → 0.95); the LLM falls back to a second provider.
- [0011 — Ingestion, second pass: font repair instead of OCR, page cleaning, structure-aware chunking, contextualized embedding input](0011-ingestion-font-repair-and-structured-chunking.md) - Four baseline shortcuts replaced, one eval run each — fonts lacking a ToUnicode map are repaired from Arial's glyph order (no OCR), furniture is stripped, and the embedder sees document and section ahead of the text.
- [0010 — Developer UX: .env.example, make install, Python ≥ 3.12, foreground compose behind a Qdrant healthcheck, ingestion progress logs](0010-developer-ux-setup-path.md) - The setup path is a product surface: every knob committed in an example file, guarded make targets that fail naming the next command, and logs that show a long upload is alive.
- [0009 — Structured agent reply, function-derived tools, chunk ids as citation handles](0009-structured-reply-function-tools.md) - The final answer becomes a provider-enforced structured output instead of a text protocol parsed by regex; tools become Python functions whose schema the adapter derives; chunks reach the model as XML.
- [0008 — Question agent baseline: PydanticAI direct, LLM-cited references, in-process eval surface](0008-question-agent-baseline.md) - The LLM port's first adapter is a caller-owned single call; `references` are the chunks the model actually cites; the eval harness consumes the domain in-process.
- [0007 — Naive ingestion baseline: what it is and what it defers](0007-naive-ingestion-baseline.md) - The first pipeline is deliberately naive so the evals can measure each later improvement, with content-addressed ids for idempotent re-ingestion and no relational database.
- [0006 — Eval metrics and golden-dataset shape](0006-eval-metrics-and-golden-dataset.md) - Deterministic metrics gate experiments while LLM-judged ones only diagnose; ground truth is verbatim excerpts plus (document, page), never chunk ids, so it survives any change in chunking.
- [0005 — Retrieval architecture: strategy port, dual-path agent, Qdrant](0005-retrieval-architecture.md) - The read side splits into a persistence port and a strategy port so retrieval experiments are adapter swaps; answering runs a deterministic seed retrieval plus a tool over the same retriever.
- [0004 — Ports & adapters lite](0004-ports-and-adapters-lite.md) - A minimal hexagonal architecture — framework-free domain, swappable adapters per pipeline stage, one composition root — with the supremacy clause that the architecture yields to the evals.
- [0003 — Toolchain: plain pip + venv, docker-first](0003-toolchain-plain-pip-docker-first.md) - Classic pip with pinned requirements inside a venv (no uv or poetry), and Docker Compose as the official way the system is run.
- [0002 — Module documentation is co-located with module code](0002-colocate-docs-with-code.md) - The bundle is re-rooted at the repo root so each module's concepts live in the directory that defines it; `docs/` keeps only cross-cutting knowledge.
- [0001 — Documentation lives in an OKF bundle at docs/](0001-okf-bundle-at-docs.md) - _Deprecated, superseded by 0002._ OKF v0.2 is the official documentation format, rooted at `docs/` rather than the repo root.
